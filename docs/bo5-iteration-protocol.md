# Bo5 难度迭代协议 0.3

用户于2026-11-15要求最多20轮「原因分析 -> Skill优化 -> 全链路合成 -> 五次盲答 -> 难度判断」。本轮目标不是oracle BoN最大分，而是同一最终题面、同一模型配置的5份完成盲答中，仅1–2份实质答对。

## 对照与边界

旧实验保留：原案、Skill1.1.0、3/3契约通过、结构D3。其题面暴露金额角色、逐项解题检查表和追加款来源解释，固定单争点契约还使P2只能生成一个实质候选。新实验先试原案无脚手架视图，再使用明确虚构的衍生合同、流水和担保情景。虚构材料不冒充原案证据或真实裁判；真实法条使用已冻结的官方全文，不继承变更事实后的旧判答案。

模型固定gpt-6-astra、high reasoning、同一轮使用相同学生材料、全新两消息上下文、无前答或评分反馈。第1–4轮每答最多10000输出token；第4轮Bo5-5明确因达到输出上限截断，保留原失败及同配置补答。从第5轮开始统一提高到20000，排除预算伪难度，旧轮次不重写、不混作同配置对照。API服务别名不认证固定权重或跨家族独立。无费用报价，不声称免费。新实验预算与旧12次预算分开：最多20轮，最多360次网关提交，总输入预留上限600万、输出预留上限360万token。每次提交前登记；无usage的失败预留用量且计入请求数。不得调用其他付费接口绕过预算。

## 每轮

1. 先从上一轮审计定位难度机制，而不是只加实体、字数、输出字段或计算精度。记录可反驳的修改假设及其来源。
2. 保存完整不可覆盖Skill快照与差异；P0确定性标准化，P1提取有据依赖图，P2使用3个独立假设规则结构示例。种子不进入P3/P5/P6或学生材料，PLawBench全部不参与生成。

   第6轮起进一步采用中性原始记录投影：同流水号、银行未执行通知和双方补充协议完整保留，删除整理者的归属总结及S12责任状态检查表。该改动来自早期各法律状态全部正确的观察，并非删掉必要事实；P3仍独立检查充分性。

   第8轮起加入S13的一笔25000元付款，双方限定用于B/C但不选择二者之一：保证是否存续决定担保比较，再依民法典第560条选择清偿债务，最后影响B/C未偿余额。保全的一般保证不能因存在先诉抗辩就被当作已消灭担保。所有到期事实、其他担保的不存在及付款范围均明确提供；新的B_protected_total指扣除付款后的受保护未偿余额，不与此前无该付款的字段值混作严格对照。此法律解释仍需P4/P6及专家复核，不能由程序分支自我认证。

   第9轮起用原始保证条款及起诉、送达、撤诉、再诉、收件签名记录替换简单催告/起诉事实。保证类型、约定不明的期间、两种保证的撤诉效果和是否成立新保证共同决定B/C的担保存续，进一步影响S13的抵充。适用的担保司法解释第25、31、32、34条先从最高人民法院官网下载冻结，另存`guarantee-authorities.json`，只交给第9轮及以后，不追补旧轮次。此修改是对前轮法律分支高成功率的待检验机制，不预设它能达到目标。

   第10轮起针对第8轮P6观察到的整体上限遮蔽，B的合同利率改为13.20%，保护上限仍为14.80%，重新复算全部参考。借据归档次数、日期和精度不增加，使逐期合法结息结果不能总被整体上限替代。该变化不是同配置原题的复测，也不预设它能降低法律分支正确率。

   第11轮起进一步区分2019年成立的C借款与2022年成立的C保证，付款跨越2020-08-20的规范边界。题设明确旧期间适用请求、起诉时报价及早期合同清偿顺序，参考按旧期间23.50%与之后14.20%的合法利率逐段复算；学生不接收研究者的利率分段标签。同时新程序记录改为B撤诉前未送达、C在期间内再诉。旧输入不覆盖，每轮P3/P4/P6重新审核其充分性和法律根据。

   第12轮起的预备机制是B共同保证：对甲各自担保全部、内部约定相互追偿各50%；甲对戊及时起诉并送达，但未在期间内对庚行权。以担保司法解释第13、29条核对戊主张的丧失追偿减免，并比较B部分担保与C全部担保，另核对戊可立即支付的最高金额。该比例参考不是裁量上限的机械取值，必须经过P3/P4/P6支持才能进入难度判断；未实际执行的准备不计入轮数。

   后续预备对照：第13轮各自独立合同且无内部追偿；第14轮对两人均及时催告。第13轮起的C起诉时报价题设改为3.25%，SP双方约定在两债都到期、同等资信且全额担保时比较依法可请求的现行年利率，不使用不可强制请求的名义利率。第15—18轮分别引入付款之后第三人的全部/部分债务加入或一般保证；第19—20轮引入付款之后全部/部分免责债务转移，区分原借款关系余额与乙本人责任。新条文均从已冻结官方全文提取，工程参考重新建立；准备不等于执行，更不等于高难结论。
3. P3只看最终题面和学生输入。信息不足、含糊、答案泄漏或不支持设定任务则修复或隔离，不把不可回答叫高难。
4. P4根据来源与可复算工程参考生成短依据。衍生情景的财务参考以Decimal计算，所有原始数字、事件和法条保留。未经专家审核，不称法律金标。
5. 冻结题面、材料、参考和verifier哈希，再运行Harbor/Smol oracle、nop及5次真实文件代理盲答。代理不能读取隐藏答案或执行任意模型shell。
6. P6逐答作语义审计；核心金额、适用规则和决定性边界都须正确。格式等价、来源顺序、措辞不作为法律错误。格式、截断、基础设施和问题不成立分别报告，不能用它们凑1–2/5。
7. 只有5次有效完成且审计认为问题可回答、参考有据、难度不是格式/纯堆量造成时，才统计目标。命中1–2/5后冻结全部输入，另做5次新的确认及审计；两组都命中才提前结束。确认失败继续下一轮，原命中不隐藏。

本协议最多20轮，而不是必须20轮。不可修复的原始材料缺口、预算耗尽或持续基础设施故障可提前结束并报告原因。停止并不代表高难任务已成功。

## 发布

第13轮起在确认本机32GB容量后，五答可以在五个独立Harbor环境并发；每个环境配置2GB。只改变执行调度，不改变输入、允许工具、模型、推理或输出预算。全部五答都归档，用量预留加锁，任何失败仍按原先具名有界补答和错误分类处理。

第14轮起P3/P4/P6仅加载完整Skill的通用质量规则投影及该轮审核数据，不再携带入口末尾的上一轮计数建议与修改假设。生成P1/P2仍读取完整本轮Skill。请求记录投影名称与完整Skill指纹；旧审核请求原样保留，早期审核可能受历史预期影响，不冒称完全隔离。

同日起P4未明确支持工程参考时即在盲答前隔离，记录为参考审核拒绝，不启动五答并不把它计为0/5。此前已完成运行的P4和P6保留原样；最终审计逐轮核对参考支持状态。

第15轮起的新材料投影进一步删除整理者预写的责任推论，保留完整义务条款、签名与双方约定。SP-01的09:20到账、第三人文书13:40签署、16:10追加诉请由中性记录给出，不另提示法律上的追溯与否；外部范围与内部追偿由原合同条款判断。加入明确标为单方法律主张的书面意见，模型需以原件和规范检验，不能将其当作认可事实。输出契约不列保证状态和第三人类型答案菜单，但保留字段口径并允许语义等价。金额参考的事实基础不变，所有后续新题仍经P3/P4/P6核验；该改动不覆盖第14轮及更早材料，也不声称已经降低成功率。

第14轮P6发现旧固定检查器允许最终金额偏差0.01元，与该轮语义审计的“最终取分须正确”不一致。第15轮冻结前修正新任务的固定检查器：十进制解析、四舍五入到分后比较，差一分须失败；未取分金额若正确取分则通过。旧任务内冻结的检查器、分数及P6不改。此修正只让固定检查符合已声明的金额口径，不把数字失误重新命名为法律推理失败。

第13轮P6发现工程参考错误地援引尚不存在的S14，整轮难度验收被拒绝；其原参考和4/5计数保留。第14轮在P4、P6、盲答或冻结尚未发生前，仅修复该研究者参考的来源说明，原版存`engineering-reference-v1.json`；学生材料、问题及expected金额状态均不变。修复拒绝触碰已被P4/P6使用或冻结的参考，早期P1/P2/P3均不接收工程参考，因此无旧模型输入被改写。第15轮以后真实包含S14，无需此特定修复。

第6轮模型曾在JSON前说明没有写文件工具，原冻结检查器返回格式错误，不能当作法律错答。第7轮起适配器0.3.0明确宿主负责写入结果；模型、推理、总预算和允许工具不变，旧轮次的系统提示、输出和检查结果不修改。最终审计可对单一JSON对象的说明前缀作非评分的法律状态字段归一化；存在多份对象时不选择最有利的一份。

第10轮起题尾也统一为学生返回JSON、宿主落盘；同题五答最多并发2个，网关账本加锁预留与合并用量，模型、输入及总预算不变。第9轮审计将不影响最终取分的约0.0068元中间展示偏差计为整体错误；保留原报告，不追溯改判。后续轮次在盲答前于输出契约固定分层口径：法律分支、最终金额、依据分别报告；中间展示偏差不超过0.01元且不改变最终取分、规则、日数或公式时只作质量提示。决定性法律、日数、公式或必答金额错误仍为实质错误。

全部情景属于dev难度校准，不再声称未见test。观察到1–2/5只是单题同家族小样本表现，并有适应性选择偏差；不是泛化难度或训练收益。命中难度也不自动消除材料权限、法条解释、隐私和专家审核门槛；训练导出保持隔离，除非另获正式准入。
