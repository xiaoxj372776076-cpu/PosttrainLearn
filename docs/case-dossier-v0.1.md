# 诉讼案件全景记录 Schema 0.1

统一产物是案件全景记录 Case Dossier，而不是最终判决摘要。一个稳定案件 ID 连接多个程序、材料版本、诉请、事实命题、举证质证和裁判。数据记录的是谁在什么阶段依据什么材料主张或认定了什么，不把各方陈述压成无来源的统一事实。

本版采用 `schema_version=0.1`，案件内容另有 `dossier_version`。现有 Skill 1.1.0、material_pack 1.0 和训练样本契约 1.1 保持不变；本 schema 是整案研究层，不能直接冒充已经通过 Skill 准入的训练材料包。

## 数据模块

| 模块 | 内容与关系 |
|---|---|
| case_metadata | 稳定 case_id、标题、法域、整理截止时点、版本、脱敏与使用权限。案号放在各程序中，不用案号合并不同纠纷。 |
| proceedings | 每个程序独立 ID，记录法院、案号、类型、时间、状态。用 appeal_of/retrial_of/remand_of/enforcement_of 连接，允许分支。 |
| documents | 文书、笔录、证据等的清单、制作者、提交者、形成/提交/取得时间、取得范围、版本与全文定位。 |
| participants | 统一主体 ID、匿名显示名、各程序中的角色与关系；真实身份映射留在私有侧。 |
| events | 事实与程序两类时间线。记录日期精度、区间、不确定性、陈述主体和来源，时间排序不改变信息的证明状态。 |
| claims | 每项诉请、反诉或抗辩的提出者、程序、版本、金额角色、理由、变更/撤回/备位关系。 |
| fact_propositions | 待判断的原子事实命题，不在这一层宣告真假。 |
| assertions | 谁对哪个命题作何陈述，态度、程序和时间；不答辩不是承认。 |
| evidence_items | 证据对象、原始编号、提交者、证明目的、关联命题和原件取得状态。 |
| evidence_responses | 按证据、主体和程序记录质证异议与回应；未取得笔录不能补造质证。 |
| court_assessments | 每个阶段法院对事实/证据的认定、范围、公开理由和原文，不使用全局采信标签。 |
| issues | 连接诉请、事实、双方陈述、证据、质证、认定、规范和裁判的争点卡。区分法院明确处理与整理者归纳。 |
| authorities | 原文引称、条号、版本线索、适用时点、效力核验；引用条号不等于取得适用版本全文。 |
| amount_ledger | 实际交易、合同记载、请求金额和裁判金额分开。用十进制字符串记录金额，重复叙述关联同一对象，不按数值相等合并。 |
| decisions | 判决/裁定/调解的逐项结果、义务主体、条件、期限、费用、生效状态及后续改变范围。 |
| gaps_and_review | 材料缺口、矛盾、OCR 和法律版本问题；记录实际审核范围与修订历史。 |

## 共同记录约定

数组始终为数组。主要记录具有 `id/title/text/support_span_ids`，并通过 `proceeding_id/actor_id/fact_ids/evidence_ids/assessment_ids/authority_ids/decision_ids/amount_ids` 等有类型引用连接。机器校验必须拒绝悬空、重复和跨错类型 ID。关键引用还须检查所属程序一致。

来源片段具有 `id/document_id/text_version/locator/quote/view_sha256`。本案使用保留原始行号的 paragraph_id；字符定位若采用区间，必须写明 Unicode code point 和左闭右开。脱敏 quote 明确属于展示视图，不冒充原件逐字引文；原文与视图指纹分开。

每个文档明确取得类型：`published_judgment_view` 是法院公开文书脱敏视图，`judgment_reference` 只是文书提到的证据，`original_obtained` 才表示取得原始证据文件。证据存在、证据内容、证明目的、法院采信与研究者已核验是不同字段。

缺失状态使用 `not_available/not_mentioned/unreadable/not_extracted/not_applicable/withheld/unresolved`，不得从 null 推导没有发生或被法院否认。空质证数组在 gaps 中解释为笔录未取得，不解释为双方没有异议。

事件日期、材料形成日期、提交日期、研究取得日期及某主体可获得信息的日期各自记录。只有一份事后判决书时，不能声称已经还原真实庭前知识视图。预测任务必须另行构造截止时间安全视图并核验可获得性。

## 金额与裁判沿革

金额角色至少区分 bank_disbursement/contract_face/claimed_principal/claimed_interest/claimed_penalty/actual_transfer/prepaid_interest/claimed_net_interest/court_return/fee/rate。实际转账的汇总对象与子项不能同时计入同一个求和；同值但不同角色保留不同 ID。金额计算使用定点分值，写明公式与每个操作数。

每个裁判结论都绑定程序、决策文档及来源。后续程序通过针对具体事项的关系补充，不能把旧认定覆盖为从未出现。最新观察到的判决不等于终局生效判决。相对期限保存触发条件；送达、生效或履行日期未知时不计算绝对截止日。

## 全文与人读视图

结构化 JSON 是唯一底稿；`casebook.md` 从同一底稿生成，章节顺序为案件范围、程序、材料、主体、双时间线、诉请沿革、事实及各方陈述、举证质证、认定、争点卡、金额、规则、裁判、缺口审核和全文附录。规范化 JSON 导出包含已取得的脱敏全文。完整原件、签章、版式、音视频和真实身份映射仍独立保存；文本不等价于原始证据。

本案仅取得一审判决书展示视图。未取得起诉状、原始证据、庭审笔录、后续裁判；二审、执行是否发生和裁判生效状态未知。所有证据原件状态保留为未取得，诉请和法庭事实为判决书转述。

本案的证据提交者、证据与事实之间的对应关系由整理者根据文书上下文归纳；公开文书只有整体确认语句，不应将这些关系当成原始证据目录或法院逐项采信记录。`case_metadata.inference_notes` 明确记录这一范围。

## 合成链路的边界

整案层用于材料梳理和专家复核，decision_unit 从 issues 中形成研究候选。外部传输/训练权限、法律适用版本、关键证据与专家审查未解决时不能据此批准训练样本。链路页面展示真实研究产物及待执行阶段的输入、输出、提示词与门槛，不将提示词模板、人工归纳或结构检查称为模型生成、盲答通过或专家金标。

研究归档完整性与训练准入分开：本案归档为 partial，训练准入为 blocked。机器检查证明字段、引用、来源片段和金额公式一致，不证明法律正确性、证据真实性或训练许可。
