# 质量、隔离和发布

## Pilot 而非直接扩量

默认建议先产出约 100 个候选，覆盖多个源案例、任务类型、事实长度和难度。该数字是起步建议，不是质量证明；用户的小样例请求不强制扩到 100。

执行前估算每阶段调用数、输入 token、修复轮数和费用。设置并遵守 max_calls/max_cost。批大小由 API、限流和文书长度决定，不照抄某篇论文的并发值。固定提示词和采样配置，记录实际模型版本；无法固定历史 API 别名时披露限制。

先查看每阶段真实通过率和失败原因，再决定扩量。高弃用率优先修选题/证据覆盖，不能仅把验证器改成容易通过的措辞。

## 单条硬门槛

| 检查 | 必须检查的事实 | 失败处理 |
|---|---|---|
| 权限 | 来源可用于本次处理、衍生与指定导出 | unresolved/fail 不导出 |
| 材料整理 | 所用字段原文对齐、身份关系一致、金额角色清楚，缺失未被编造 | 修包或隔离相关单元 |
| 原文对齐 | 关键事实/结论与真实原文一致，引用区间能复核 | 修定位或隔离 |
| 可回答性 | 题面包含必要事实，目标与上下文约定明确 | 补证据，不补造事实 |
| 引用 | 条文存在、版本正确、在本题时点/法域可适用 | 权威查询或专家核验 |
| 答案支持 | 证据和规则支持实际所问的结论 | 修复并重新盲答 |
| 盲答 | 新上下文独立作答，实质结论一致且依据充分 | 隔离分歧，不投票掩盖 |
| 数值 | 项目归属、重复项、净额/总额、单位和舍入正确 | 程序复算和项目审核 |
| 脱敏 | 人名、号码、位置、组合身份线索等处理有效 | 改写后重核事实 |
| 泄漏 | 与保留评测没有题目/案例/标签衍生重叠 | 隔离，不通过改名逃避 |
| 派生一致性 | 非实质改写未变答案；反向主张有明确反驳 | 按新情景核验或放弃 |
| 难度适配 | 最短合理解答需要目标层级的推理，而非长文本或标签自评 | 换单元、修题或显式调整目标 |

Accepted 不能有 fail/unresolved/remaining_issues。软指标如自然度、冗余、题型覆盖、难度用于排序，不能抵消硬错误。

法条是否真实/有效须有实际核验依据。已知案件日期与法条版本不一致时不能默认用现行法修正历史案件。对“该案法院如何判断”和“截至某日的一般法律规则”分别设任务，不混用标签。

## Few-Shot 与难度验收

使用经核验 seed，按任务与推理结构选择并记录，不把测试题放进示例。检查模板复制、跨案事实移植、固定答案锚定和 seed 使用过度集中。完整规范见 [Few-Shot 与难度](few-shot-and-difficulty.md)。

对 D3/D4，审定最短合理解答所需的操作，并记录这些操作如何依赖事实、证据和规则。不能为了通过门槛枚举几个虚假的推理模式。P3 不看预设答案，P6 结合盲答复核，均不接收生成用 seed 答案。

在相同材料、同教师和相近 token/调用预算下比较零样本与 few-shot 的 pilot。记录可回答率、真实 D3 合格率、错误率、近重复、覆盖率与种子集中度；不是只对比自评难度或长答案占比。zero-shot 仅用于显式消融，不静默代替缺失 seed bank。

## 数值与裁量

金额结果用 Decimal 或等价十进制定点逻辑复算。首先验证每个项目为何计入/排除：犯罪所得、损失、退赔、利息、保险、诉讼费等不是同一种金额。正确加法不能替代法律项目归属。

精确量刑通常包含裁量。若题面没有原案足够信息，不把教师输出的月数叫唯一金标。可转为原判刑期提取、量刑情节解释、明确法定区间判断；任何转任务都要修改规格并记录，而不是偷偷换题。

反事实任务应给出严格变更清单和新标签取得方法。改变金额、日期、故意/过失、行为或证据后，原案结果不再自动可用。未能取得可信新标签就不发布。

## 防止 Benchmark 污染

评测集及答案不是生成素材。可学习公开任务说明和输出格式，可使用 benchmark_train/official_example/独立种子；development 一旦用来出题就属于开发数据。

建立 protected evaluation manifest，包含保留题目身份、源案件规范 ID、输入指纹和必要的近重复审计信息。原始测试题只由隔离的本地审计流程处理，不交给 writer、修正器或盲答者作示例。

先做规范化精确去重，再做近重复候选检索和人工/独立模型复核；覆盖问句、事实主体、案例身份及语义关系。相似度阈值需通过样本标注校准，不声称一个通用阈值能保证不泄漏。审计器的精确问题检查不能代替这一步。

同一目标案件、判断点、正反变体、匿名化/翻译/压缩版本、直接/解释包装必须同组。多案组合题用关联组件切分。训练中共用法条不等于案件泄漏；切分目标是未见案件/问题时，规范库可保持固定并披露。

若 benchmark 测试题已经进入生成上下文，去重不能撤销测试参与开发这一事实。换用未接触的新评测集，或披露 test-informed 设置，不再称严格未见评测。

## 人工审核与发布等级

自动核验通过的数据默认是 experimental。模型一致性不是法律正确率；样本审查通过不能证明整个数据集无错。

Pilot 建议抽审至少 30 个 accepted，并检查部分 rejected/quarantine，覆盖每种任务、源材料、裁量问题、数值和分歧案例。没有专业审核资源时记录这一缺口，不伪造审核。该样本量是工作起点，不能用来承诺错误率。

评估报告区分：单条 human_reviewed、数据集抽样 expert_audited、全部人工审核。只有每条实际审核的记录才设置 human_reviewed。对发布者声明的高质量等级，明确抽样方法、样本量、审核资质、分歧与限制。

发现严重错误时隔离相关模板/来源/标签分层，调查根因并重跑受影响检查，再扩大人工抽审。不要只删掉被发现的几条后继续把全库称为可靠。是否发布必须符合用户指定用途和审核标准。

## 实际计数与训练验收

分别报告：原材料、标准化材料包、种子与实际选择、单元、候选、唯一问题、目标/审定难度、通过/失败/隔离、训练行数。一个问题展开为 direct 和 answer_with_rationale 两行，仍是一道问题。报告去重前后数量、每阶段删除/改写数量、模型/任务/案例分布和版本。

先验证导出与标准化记录一一对应：parent_sample_id、split、问题、最终答案和数量守恒。训练 API/工具运行后读取实际日志，不能把已有论文收益当作本轮效果。

建议做同模型同预算的数据消融：原始草稿、证据选题、独立校验、解释监督。保持唯一问题数或 token 预算可比，避免把更多训练行带来的收益误认为方法更好。使用固定的独立评测，分别看正确性、引用支持、拒答/信息不足、数值结果和泛化，不能只汇总语言风格分。

## 本地审计器的边界

`scripts/audit_release.py` 仅验证显式数据契约：状态、字段、检查枚举、材料包关联、难度元数据最低结构门槛、few-shot 记录、权限标签、分组、精确重复和禁止种子角色。非 accepted 记录只用于计数和分组审计，不被导出。

脚本可拒绝明显不合格发布，但它不抓取来源，不验证材料包文件或 pass 背后的日志，不复算法条，不证明真实推理难度，也不能证明近重复检出率。即使退出码为 0，仍须完成上游证据核验、独立审核和用户要求的人工验收。
