# Few-Shot 种子与真实难度

## 两个输入的分工

材料包/命题单元约束“哪些事实、规则、结论有依据”；种子示范“如何将这些材料组织成需要推理的问题”。不能从种子继承法条、事实或答案，也不能因目标种子复杂就向新案例添加复杂情节。

先匹配任务、必要推理结构和目标难度，再考虑主题相似性。最像同案/同法条的问题不一定是最佳 few-shot，会增加抄题、近重复和答案锚定风险。

## Seed Bank 契约

每条 seed 保存：seed_id、来源角色、许可、任务标签、司法辖区/时点、question、answer、简短 rationale、已核验来源、reasoning_patterns、difficulty_level、difficulty_basis、quality_review、内容哈希。

只有来源允许、答案有据、题面自包含、无评测重叠且通过审核的 seed 才可标 eligible。人工写的题也需校验；benchmark_train 的答案不因来自 benchmark 就自动正确。保留核验时点，跨法域示范先抽象成逻辑结构模板，不传递具体法律结论。

question/answer/rationale 是 few-shot 的主要展示内容。difficulty_basis 解释哪些推理确有必要，reasoning_patterns 使用如下标签：

| 标签 | 要示范的能力 |
|---|---|
| `information_extraction` | 从原文识别指定事实，不假装深推理 |
| `rule_application` | 将已知事实映射到规则要件 |
| `arithmetic_computation` | 执行已确定项目的计算，不把直接加法当复杂法律推理 |
| `multi_condition_application` | 联合检查多个决定性条件，不是枚举无关事实 |
| `exception_check` | 一般规则与例外边界的辨别 |
| `evidence_comparison` | 依据内容比较证据、解决事实冲突 |
| `temporal_applicability` | 判断行为时间与规范版本/程序时点的关系 |
| `amount_classification` | 识别哪些项目计入、扣除或重复 |
| `multi_issue_composition` | 联动多个有关系的判断点 |

不要把全文内部思维过程作为 seed 必填项。rationale 是可核验的简短证明/解释，能够示范推理结构即可。

## 选择与提示拼接

默认通常 2-4 条示例，配置默认 3。不是必须越多越好；长示例可能挤掉关键事实或诱发模板复制。

1. 先过滤来源角色、权限、审核状态、法域/时点和 protected evaluation 重叠。
2. 在相同任务内，优先选与目标单元可支持的 reasoning_patterns 相匹配的例子。
3. 至少有一个例子达到目标难度，其余展示不同条件/例外/证据结构；不全是同一模板的改名版。
4. 检查新材料和示例没有同案、近重复、同答案锚定；优先保留不同事实外观的结构匹配。
5. 记录 few_shot_run_id、seed_ids、选择理由、示例顺序、目标难度、完整提示哈希与 token 预算。

不足时建设小型经核验 seed bank，或请求用户提供合格示例。不静默退回零样本生成；显式 zero_shot_ablation 必须有 experiment_id 且另行统计，不假称已采用 few-shot。

推荐 P2 提示由四部分组成：任务/难度要求、经筛选示例、目标材料单元、严格输出契约。示例采用统一结构：任务 -> 自包含问题 -> 正确答案 -> 简短依据 -> 必要推理操作 -> 为什么不是简单查找题。

P2 输出先只取候选问题和出题依据，gold answer 在 P4 使用新案例来源单独生成。若 P4 也需格式示范，只使用结构模板或经许可的解释样式，不让种子法律结论替代目标依据。

P0/P1 不接收这些出题示例，防止整理时向案例补入示例事实。P3/P5/P6 不看生成用示例答案，以免形成同一答案锚定。除非明确在训练上下文学习任务，few-shot 不导出到学生输入。

## 难度定义

难度以最短合理解答所需的操作判断，不以答案长度、引用数量或生成器自评判断。

| 层级 | 设计依据 |
|---|---|
| D1 | 单字段提取、直接原文查找、几乎直接给出答案 |
| D2 | 单一规则对明确事实的一次应用，或不含项目争议的直接计算 |
| D3 | 至少两个必要操作，且含条件组合、例外、证据比较、时点或金额归属等非直接查找环节 |
| D4 | 多争点联动或多阶段关系，至少三个必要操作，所有关联和条件均有材料依据 |

例如“法律条文是什么”通常是 D1；即使题面很长也不自动变难。一个问题同时涉及规则适用与必要的例外判断可设计为 D3，前提是两者都确实影响答案。直接提取任务可以合法停留 D1，不应为了难度配额换任务。

每题 difficulty 保存 target、assessed、reasoning_requirements、assessment_reason、assessment_run_id。reasoning_requirements 的计数只是最低结构门槛，不能证明推理操作真的必要；P3 与 P6 需用题面和证据复核。

## 反捷径测试

对候选题问以下问题，不通过时修改或淘汰：

- 只复制一句答案侧原文、匹配法条名或某个关键词是否就能作答？
- 去掉生成器声称必要的某一步，结论是否仍显而易见？若是，该步骤不计入难度。
- 所谓复杂性是否只是叙事长、实体多、否定句多或额外塞了几个法条？
- 是否通过删除必要事实、制造指代歧义或要求裁量唯一值让模型“觉得难”？
- 问题能否明确要求比较、适用例外、判断项目归属，但不直接提示结论？

材料只支持 D2 时，换一个有据单元，或显式调整目标并记录变更。不能保留 D3 标签却用冗长解释掩盖简单题。

## 示例对照: 说明推理结构，不提供虚构法律金标

下面只是逻辑形式演示。规则明确是假设规则，不代表任何法域法律；需要用于真实生成时，换成有来源并核验过的示例。

### 示例 A: 条件与例外

假设提供规则 R1：“达到条件 A 且满足条件 B 时适用结果 X”；R2：“若事实 C 被证据证实，则适用例外 Y”。材料明确给出 A、B 的事实、关于 C 的两份证据及判定证据是否足够的规则。

简单题：R1 规定了什么？这是直接查找，不足以示范 D3。

较好的示范题：根据给定事实与证据，该情形应适用一般结果 X 还是例外 Y？说明决定结论的条件与证据。

示范解释应展示：核对 A/B -> 比较关于 C 的证据 -> 判断例外是否成立。不能先认定 Y 再给它编一段解释；若材料没有证据判断规则，问题就不完整。

### 示例 B: 金额项目归属

假设题目明确规定“求未清偿本金，不计利息和费用”。给出两笔本金 10,000 与 5,000、已归还本金 3,000，以及 500 的费用，并说明一处重复出现的 5,000 是同一笔。

简单题：10,000 + 5,000 等于多少？只示范直接计算。

较好的示范题：截至给定时点，尚未清偿的本金是多少？哪些项目应排除或避免重复计算？

该虚构规则下可复算为 10,000 + 5,000 - 3,000 = 12,000，费用不计，同笔金额不重复。这示范“项目归属 + 去重 + 净额计算”，不能把排除费用的假设迁移为真实法律规则。

## Pilot 观察

分别统计目标与审定难度、可回答率、盲答分歧、模板相似度及 seed 使用集中度。做少量相同材料/模型/预算的零样本与 few-shot 对照，观察 D3 合格题占比，而不是仅比较模型自评的难度分。

Few-shot 能提供难度示范，但是否提高高质量难题产出须实测。过度围绕少数困难 seed 出题会损失覆盖率；同时保持任务、推理结构和案例来源多样性。
